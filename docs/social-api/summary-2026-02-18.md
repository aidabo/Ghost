# Backend Functional Report (Last 2 Weeks)

## 1) Social Components / Page Builder
### Functional Changes
- Added/expanded `social_components` support for:
  - `group_id` scoped pages
  - `tag` (category) usage
  - published lifecycle handling (`published_at` auto set/clear by status)
- Content API public scope refined:
  - returns published pages without group
  - returns published pages in `public` groups
  - no login required for those scopes
- Admin API group-aware permission checks added for read/write.

### API Caller Spec
- `GET /ghost/api/admin/social/components`
  - Query: `group_id`, `filter`, `limit`, `page`, `order`, optional `tag`
  - Auth: staff session required
  - Behavior: group access validation for non-public group data
- `GET /ghost/api/admin/social/components/:id`
  - Query: optional `group_id`
  - Auth: staff session required
- `POST /ghost/api/admin/social/components`
  - Body:
    ```json
    {
      "socialcomponents": [{
        "type": "page",
        "title": "Page title",
        "group_id": "<groupId|null>",
        "tag": "category",
        "status": "draft|published"
      }]
    }
    ```
- `PUT /ghost/api/admin/social/components/:id`
  - Body: same model fields as add
- `GET /ghost/api/content/social/components`
  - Public browse/read for published pages in allowed public scope.

## 2) Group + Tag Access Rules
### Functional Changes
- Group rule alignment:
  - `type=public`: readable without user auth
  - non-public groups: read/write requires group member auth
- Tag endpoint supports group-aware counting/filtering in admin-side flows.
- Host routing guidance:
  - public groups should be queried through the Content API
  - private groups should continue to use the Admin/Dashboard API path with auth
  - if a client needs to support both, it should select the endpoint by group type before issuing the request

### API Caller Spec
- `GET /ghost/api/admin/tags?include=count.posts&group_id=<groupId>`
  - Returns tag counts scoped to group posts.
- `GET /ghost/api/admin/posts?group_id=<groupId>&filter=...`
  - Group-aware post query with permission checks.
- `GET /ghost/api/content/posts/?group_id=<groupId>`
  - public-group-only browse/read path without member auth

## 3) Gallery System (Users + Groups)
### Functional Changes
- User/group gallery storage path separation:
  - `gallery/users/<u_alias>/YYYY/MM/...`
  - `gallery/groups/<g_alias>/YYYY/MM/...`
- Added user/group media folder alias columns and lazy generation behavior.
- Upload endpoints accept `group_id` and optional tag mapping (`tag`, `tag_slug`, `tag_id`).
- Added gallery listing APIs + pagination cursor + type filter.
- Added `social_media_assets` mapping for asset-to-tag metadata.
- Added sync endpoint for post publish/tag change flows.
- Added direct-upload support for large gallery assets:
  - Ghost admin API can issue presigned S3 PUT URLs using existing gallery path rules
  - upload target path still respects:
    - `users.media_folder_alias`
    - `social_groups.media_folder_alias`
  - finalize step registers uploaded asset into `social_media_assets`
  - intended for large `video`, `audio`, and generic `file` uploads while keeping existing small-file upload endpoints available

### API Caller Spec
- Upload:
  - `POST /ghost/api/admin/images/upload?group_id=<id>&tag_slug=<slug>`
  - `POST /ghost/api/admin/media/upload?...`
  - `POST /ghost/api/admin/files/upload?...`
- Direct upload presign:
  - `POST /ghost/api/admin/social/gallery/presign`
  - Body:
    ```json
    {
      "filename": "clip.mov",
      "content_type": "video/quicktime",
      "content_length": 734003200,
      "group_id": "<optionalGroupId>",
      "tag": "<optionalTagName>",
      "tag_slug": "<optionalTagSlug>",
      "tag_id": "<optionalTagId>"
    }
    ```
- Direct upload finalize:
  - `POST /ghost/api/admin/social/gallery/finalize`
  - Body:
    ```json
    {
      "storage_key": "gallery/users/u_alias/2026/03/clip.mov",
      "storage_url": "https://cdn.example.com/.../clip.mov",
      "asset_type": "video",
      "group_id": "<optionalGroupId>",
      "tag": "<optionalTagName>",
      "tag_slug": "<optionalTagSlug>",
      "tag_id": "<optionalTagId>"
    }
    ```
- List user gallery:
  - `GET /ghost/api/admin/social/gallery/user?limit=100&next_cursor=<token>&type=<all|image|video|audio|file>`
- List group gallery:
  - `GET /ghost/api/admin/social/gallery/group/:id?limit=100&next_cursor=<token>&type=<...>`
  - or `GET /ghost/api/admin/social/gallery/group/?group_id=<id>&...`
- Sync asset tags:
  - `POST /ghost/api/admin/social/gallery/sync-tags`
  - Body:
    ```json
    {
      "post_id": "<postId>",
      "mode": "primary",
      "urls": ["https://.../file.jpg"]
    }
    ```

## 7) Large Media Upload Strategy
### Current Intended Behavior
- Keep existing Ghost upload endpoints for normal/small uploads, especially common image flows.
- Use direct upload for large `video`, `audio`, and `file` assets.
- Frontend can decide threshold by env and switch automatically.
- This keeps mobile/general post editing simple while avoiding proxy/upload timeout issues for heavy media.

### Frontend Coordination Notes
- The host frontend now uses a configurable size threshold for large media direct upload.
- Suggested env naming on host side:
  - `MEDIA_DIRECT_UPLOAD_THRESHOLD_BYTES`
- Example:
  - `52428800` for `50MB`
